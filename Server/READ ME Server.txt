FFXI 2016 SERVER
Fan Project by Habex
=======================================

You do not need to open anything in here. Use the app in the "Server App" folder.

WHAT IS IN HERE
  lsb/            LandSandBoat (the game server) as used for this project: source code, scripts,
                  settings (settings/*.lua) and modules (modules/, list in modules/init.txt).
  programs/       the four server programs (xi_connect, xi_search, xi_world, xi_map), one folder
                  per kind of computer. Computers without a folder here build their own with Setup;
                  those land in lsb/.
  proxy/          the PS2 login part (ps2proxy*.py, 2016 mode) and its maps (proxy/maps), plus the
                  friend list service for the 2016 game (soc_service.py).
  database/       ffxi_world.sql.gz, the game world. Every account, character, chat log and
                  mail table is EMPTY (list in emptied_tables.txt); profiles are made in the app.
  admin/          what the app runs inside the map server (messages, moderation).
  setup/          one time setup per computer:
                    Setup Mac.command         Mac
                    Setup Windows.bat         Windows
                    Setup Linux.sh            Linux
                    build_server_programs.sh  the build on its own (Linux, Intel Mac)
                    make_share_copy.py        a copy of the release folder without your private data
  server_control.py   start, stop and profiles (the app uses it; it also works on its own:
                      python3 server_control.py start | stop | status | check | create-profile NAME)
  server_admin.py     online players, profiles, world chat, the / commands
  server_net.py       addresses, port forwarding (UPnP), the "is it working?" check
  server_roles.py     roles for in game "!" commands (checked by lsb/modules/lan_roles)
  server_chat.py      chat rules, scheduled messages, chat history (the rules run in
                      proxy/ps2proxy_chatrules.py, so they apply to every player)
  data/           made at the first start: the private database (port 3316, only this computer),
                  players.txt (profile passwords for the PS2 sign in, keep it private), roles, chat
                  rules, chat history (chat.db), logs. Leave data/ out when you share the release folder.

START ORDER (what Start Server does)
  database, then login (xi_connect), search, world, map, the PS2 login part and the friend list.
  The database is a private MariaDB that keeps its files in data/database; it never touches another
  MariaDB on the computer.

GAME UPDATES (sent to the PS2 in game)
  Your players do not need a new disc or patch for a small fix: the PS2 asks this server for updates when
  the player presses OK on the sign in page (the same address and port the game signs in to).
  Publish from this folder:
    python3 update_tool.py publish --host host2016.elf          a new game program (the 6 MB host2016.elf)
    python3 update_tool.py publish --data "ROM/12/34.DAT=new_file.dat"
                                                                a game data file; the path is below image/ffxi/
    python3 update_tool.py status                               what is published now
    python3 update_tool.py clear                                stop offering the update
  Every publish raises the version number by one. A player with an older version sees
  "A new update is available. Update now?  Yes / Return to login". Yes downloads the files (a progress bar
  shows), and the game restarts itself when a new game program came with it. Updates are only ever taken
  from the server the player typed in.
  Nothing on the disc or the original game files is changed: the files go to the hard drive as
  U_* and UPD*.TXT beside SERVER.TXT, and deleting them gives the original game back.
  A new game program that does not reach the sign in page is dropped on the next start and the program
  on the disc runs again.
